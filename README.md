# AI-Based Fraudulent Transaction Detection Database
### DBMS Lab Project — Project 11

A production-grade, collaborative database project combining relational modeling, real-time PL/SQL rule-based anomaly interception, automated fraud lifecycle management, and Machine Learning (Isolation Forest) transaction scoring.

## 🔒 Frozen Database Schema

> **CRITICAL RULE:** Table names, column names, data types, and primary/foreign key constraints are **FROZEN**.  
> Neither teammate nor AI assistant may rename or delete columns.

```sql
CUSTOMERS (
  customer_id   NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  full_name     VARCHAR2(100) NOT NULL,
  email         VARCHAR2(100),
  city          VARCHAR2(50),
  created_date  DATE DEFAULT SYSDATE
);

ACCOUNTS (
  account_id    NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  customer_id   NUMBER NOT NULL REFERENCES CUSTOMERS(customer_id),
  account_type  VARCHAR2(20) DEFAULT 'SAVINGS' CHECK (account_type IN ('SAVINGS','CURRENT')),
  balance       NUMBER(14,2) DEFAULT 0,
  opened_date   DATE DEFAULT SYSDATE
);

TRANSACTIONS (
  txn_id         NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  account_id     NUMBER NOT NULL REFERENCES ACCOUNTS(account_id),
  amount         NUMBER(12,2) NOT NULL CHECK (amount > 0),
  txn_time       TIMESTAMP DEFAULT SYSTIMESTAMP,
  merchant       VARCHAR2(100),
  location       VARCHAR2(100),
  channel        VARCHAR2(20) CHECK (channel IN ('POS','ONLINE','ATM','UPI')),
  is_flagged     CHAR(1) DEFAULT 'N' CHECK (is_flagged IN ('Y','N')),  -- Populated by Person 2
  anomaly_score  NUMBER(6,4),                                          -- Written by Person 3 (ML)
  is_fraud       CHAR(1) DEFAULT 'N' CHECK (is_fraud IN ('Y','N'))     -- Ground truth label
);

FRAUD_ALERTS (
  alert_id      NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  txn_id        NUMBER NOT NULL REFERENCES TRANSACTIONS(txn_id),
  alert_reason  VARCHAR2(200),
  alert_time    TIMESTAMP DEFAULT SYSTIMESTAMP,
  status        VARCHAR2(20) DEFAULT 'OPEN' 
                CHECK (status IN ('OPEN','REVIEWED','CONFIRMED_FRAUD','FALSE_ALARM'))
);

ALERT_AUDIT_LOG (
  log_id        NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY,
  alert_id      NUMBER NOT NULL REFERENCES FRAUD_ALERTS(alert_id),
  action        VARCHAR2(50),
  action_time   TIMESTAMP DEFAULT SYSTIMESTAMP,
  performed_by  VARCHAR2(50)
);
```

## 🛠️ Antigravity & Git Workflow Guidelines

1. **Repository Setup**:
   - Repository URL: `https://github.com/coderbaiii/AI-Fraud-Detection-DBMS.git`
   - One teammate hosts the repository; all three are added as collaborators with write access.
2. **Branching Strategy**:
   - Each person works on their dedicated feature branch:
     - Person 1: `git checkout -b db`
     - Person 2: `git checkout -b plsql`
     - Person 3: `git checkout -b ml`
3. **Workspace Isolation**:
   - Edit **only** files inside your allocated folder (`/sql`, `/plsql`, `/ml`).
   - Never alter another member's files without team agreement.
4. **Daily Sync Cycle**:
   ```bash
   git checkout main
   git pull origin main
   git checkout <your-branch>
   git merge main
   ```
5. **Merging**:
   - Once a milestone is tested, push your branch and open a Pull Request to merge into `main`.
